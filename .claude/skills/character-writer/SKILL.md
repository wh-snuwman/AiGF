# character-writer

이 프로젝트(Ollama gemma3:12b 로컬 모델 기반 디스코드 봇)의 캐릭터 파일을 **짧고 말이 꼬이지 않게** 만든다.
상세 규칙은 `docs/캐릭터_작성_가이드.md`, 파일 목록/명령은 `config/characters/README.md` 를 따른다. 작업 전에 가이드를 한 번 읽는다.

## 절차
1. **요청 정리**: 캐릭터 이름, 출처(원작이 있으면), 분위기, 반말/존댓말, 말 많은 정도를 사용자 말에서 뽑는다. 부족해도 합리적으로 정해서 진행하고, 가정한 점은 마지막에 한 줄로 알린다. 원작이 있으면 필요할 때만 웹에서 설정을 확인하되 **대사·가사는 인용하지 않는다**.
2. **id 정하기**: 영문 소문자/숫자/_ 2~24자. 이미 있으면(`config/characters/<id>.yaml`) 덮어쓰지 말고 물어본다.
3. **템플릿 생성**: `python scripts/new_character.py <id> "<이름>" <프리셋>` (프리셋: default/gentle/tsundere/energetic/cool).
4. **내용 작성** (생성된 파일을 Edit/Write 로 채운다). 반드시 지킬 것:
   - `profile` 1~2문장(140자 이내), `personality`·`speech_style` 각 3~4줄에 **줄당 한 문장**(60/70자 이내).
   - 말버릇을 따옴표로 나열하지 않는다(분위기로 서술). 컨셉 소재는 "가끔만"이라고 빈도를 적는다.
   - `examples` 7개 안팎: 답 1~2줄, 줄당 10~25자, **쉼표·마침표·따옴표·괄호·물결·느낌표·말줄임표 없음**, 시작 단어 서로 다르게, 인사/잡담/고민/칭찬/놀림/"너 AI지?"(부정·인정 없이 어이없어하며 화제 전환)/"ㅋㅋㅋ"/모르는 질문을 섞고 컨셉 소재는 1~2개에만. `who` 이름은 아무거나(봇이 중립 라벨로 바꿈).
   - `guard_replies` 6~8개·`fight_replies` 4~6개(각 30자 이하), `fight_style` 한 줄, `mood_baseline` 극단값 금지, `concept_hooks` 2~4개(해킹/코드 훅엔 "실제 방법은 알려주지 않고 넘긴다"), `web_topics` 1~4개.
   - AI/봇/프롬프트 언급 문구, 비서 역할, 성적/혐오/폭력 내용, 실존 인물 사칭 금지. `rules` 는 0~3개.
5. **검사**: `python scripts/check_character.py <id>` 를 실행한다. 오류(✗)는 반드시 고치고, 경고(!)는 가능한 한 고친 뒤 다시 실행한다. (로컬에 pyyaml 이 없으면 `pip install pyyaml`.)
6. **적용 안내**: 사용자에게 아래를 알려준다.
   - 서버에서 `git pull`(파일을 커밋·푸시한 경우) 후 디스코드에서 `/캐릭터 동작:부르기 캐릭터:<이름>` 또는 `/캐릭터스왑 캐릭터:<이름>`, 이미 쓰는 캐릭터를 고쳤다면 `/상태 동작:리로드`.
   - 아바타를 쓰려면 `avatar_url`(이미지 주소)을 채운다.
7. **커밋/푸시는 사용자가 원할 때만** 한다 (이 프로젝트에서는 평소 변경 후 푸시를 요청받는 편이지만, 캐릭터 파일은 만든 뒤 내용을 보여 주고 확인받는다).

## 기존 파일 고치기
- 말이 어색하다는 피드백이면 먼저 `examples` 의 기호/길이/시작 단어와 `speech_style` 의 따옴표 나열을 의심한다 (모델은 예시를 가장 강하게 따라 한다).
- 한 가지 소재만 계속 나오면 `concept_strength` 를 낮추거나 훅·예시의 소재 비중을 줄인다.
- 수정 후에도 항상 `scripts/check_character.py` 로 검사한다.

## 다른 모델에게 맡기는 경우
`docs/캐릭터_작성_가이드.md` 9장의 "모델에게 줄 지시문"을 그대로 건네고, 돌려받은 yaml 을 `config/characters/<id>.yaml` 에 저장한 뒤 5단계 검사부터 진행한다.
