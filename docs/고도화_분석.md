# 전체 고도화 명세 대비 현황 분석 (2026-11-23)

명세 원문의 항목을 코드와 대조한 결과입니다. 이미 있는 기능은 다시 만들지 않습니다.

| 명세 | 항목 | 상태 | 남은 일 |
|---|---|---|---|
| 감정 | 30종, 강도, 감쇠, 말투/길이/이모티콘/빈도 반영 | 구현됨 (`bot/mood.py`) | 주/보조 감정 개념 없음 |
| 호감도 | 유저별 값, 변화 규칙, 저장 | 부분 | 내부값은 -1~1(기본 0.1). 0~100 표기, 변경 이력 테이블(시각/사유/상황), 반복 감쇠 보강 필요 |
| 말싸움 | 시작 조건, 자유 수위, 승패, 후속 감정 | 구현됨 (`bot/fight.py`) | 재시작 시 싸움 상태 소실 |
| 메시지 큐 | 상태값, 중복 제거, 재시도, 재시작 복구 | 부분 | 큐가 메모리(`bot.pending`)뿐. 상태값 없음, 메시지 ID 중복 제거 없음, 복구는 최근 15분 멘션 1개만 |
| 채팅 비율/자율 채팅/타겟팅 | 구현됨 (`ratio.py`, `initiative.py`, `targeting.py`) | 캐릭터별 비율 설정 없음(서버 공통) |
| 스케줄/장소 | 기상/취침/활동/장소 | 없음 | 시간대 문자열만 있음. 구조화 데이터와 상태 엔진 필요 |

| 프롬프트/토큰 | 공통 프롬프트 분리, 토큰 기록 | 부분 | 토큰 예산 계산기 없음, 단계별 압축 효과 측정 없음 |
| 로그/통계 | JSONL trace, 사용량 DB | 부분 | P50/P95 없음, 감정/호감도 시계열 없음, matplotlib 그래프 없음, 관리자 GUI(Select/Button/Embed) 없음 |
| 명령 | 슬래시 명령 12개 | 구현됨 | `/캐릭터`와 `/캐릭터스왑` 중복, `상태`라는 이름이 3곳, `/사용량`과 `/로그 통계` 중복 |
| 보안 | 인젝션 방어, 관리자 검사, 파라미터 바인딩 | 구현됨 | 의존성 취약점 점검 미실시 |
| 테스트 | 30건 | 부분 | 감정/호감도/싸움/큐/persona 테스트 없음, 벤치마크 없음 |
| 캐릭터 외형 프롬프트 | 외형/표정/장면 프롬프트 | 부분 | yaml 에 필드 없음(아바타만) |
| 캐릭터 생성 스킬 | 단일 스킬 | 부분 | 8단계 하위 스킬 구조 없음 |

## 성능 기준값에 대해
개발 PC 에는 GPU/Ollama 가 없어 TTFT, 응답 지연, VRAM 은 측정할 수 없습니다(`data/logs` 는 가짜 모델로 만든 테스트 기록).
실측은 서버에서 해야 하므로, 측정 스크립트(`scripts/bench.py`)를 만들어 서버에서 한 번 돌린 결과를 기준값으로 삼는 순서로 진행합니다.

## 진행 순서 (제안)
1. 데이터 기반: 호감도 이력 테이블, 메시지 상태 큐, 토큰/지연 통계(P50/P95)
2. 운영: 감정/호감도 그래프 생성, 관리자 GUI, 명령 정리
3. 캐릭터: 스케줄/장소, 호감도 단계별 말투, 외형 프롬프트
4. 성능: 서버 벤치 -> 토큰 예산 -> 보조 교정 모델 검토(실측 후)
5. 생성 스킬 하위 구조화, 테스트 보강
