# 게이 계획서 3

요청 5가지: ① 가끔 인터넷에서 유행어/자기 관련 최신 정보 (느리면 안 됨) ② 정형행동(같은 말/문장 반복) 원인 분석과 해결
③ 거절·회피 표현 다양화 ④ 보안 전체 업데이트 ⑤ 캐릭터 추가 시 감정 설정 변경 최적화.

## 0. 자료 조사 요약 (정형행동 = 반복)

| 출처 | 핵심 |
|---|---|
| Ollama/Gemma 3 모델 파라미터 | Gemma 팀 권장: temperature 1.0, top_k 64, top_p 0.95, min_p 0.0~0.01, **repeat_penalty 1.0**. Ollama 기본값은 repeat_penalty 1.1 / repeat_last_n 64 |
| 샘플링 가이드(smcleod 등) | repeat_penalty 는 자연스러운 반복(조사, 어미)까지 깎아 어색한 말을 만든다. presence/frequency penalty 는 0~0.5 범위에서 약하게 |
| 반복 루프 연구(arXiv 2512.04419 등) | 자기 출력이 다시 컨텍스트로 들어가 **반복할수록 반복 확률이 올라가는 양의 되먹임**. 작은 로컬 모델·긴 대화·양자화에서 심함 |
| DRY 샘플러(arXiv 2608.22761) | 직전 문맥의 정확한 반복만 억제하고, **여러 번의 독립 생성에 걸친 통계적 반복은 못 잡는다** (Ollama 에는 DRY 없음) |
| Antislop(arXiv 2510.15061) | 모델이 자주 내는 상투구는 토큰 페널티가 아니라 **빈도 추적 + 금지 목록 + 사후 처리**로 줄인다 |

### 이 프로젝트에서 반복이 생기는 원인 (코드 점검 결과)
1. **되먹임**: 대화 기록 10개 안에 봇 자신의 말이 그대로 들어가고, 프롬프트에도 `최근한말`을 다시 적어 줘서 오히려 그 표현을 따라 하게 만든다.
2. **고정 few-shot**: 예시 3쌍이 매번 똑같아서 시작 단어, 어미, 문장 틀을 복사한다 (정형행동의 가장 큰 원인).
3. **토큰 페널티 과다**: repeat_penalty 1.15 + 범위 256 은 권장값(1.0)보다 강해 어색한 대체어('걍', '됐어' 같은 한두 단어로 쏠림)를 만든다.
4. **단어 단위 감시만 존재**: 같은 시작어, 같은 끝맺음, 같은 문장 틀, 같은 이모티콘, 똑같은 한 줄 전체는 못 잡는다.
5. **고정 대체 문구**: 거절/방어/싸움 대체 문구가 8개 안팎이라 금방 소진된다.
6. **감정 톤이 1줄 고정**: 같은 감정이 이어지면 같은 지시문 → 같은 말투.

### 해결 (LLM 호출을 늘리지 않는 순서로)
- A. **샘플링 정상화**: repeat_penalty 1.15→1.05, repeat_last_n 256→96, frequency_penalty 0.25 추가, min_p 0.02. 호출마다 temperature ±0.1 흔들기.
- B. **예시 풀 회전**: 캐릭터 예시 전체에서 `max_examples`쌍을 뽑아 쓰되 `example_rotate_min`분(기본 25)마다 바꿔서 KV 캐시 이득은 유지.
- C. **되먹임 차단**: 프롬프트용 대화 기록에서 봇의 중복 줄 제거, `최근한말`은 2줄·짧게만, 대신 금지 목록(시작어/끝맺음/과다어) 제공.
- D. **다양성 추적기**(`bot/diversity.py`): 채널별 최근 봇 말풍선에서 시작어·끝맺음·전체 문장 유사도(문자 2-gram Dice)·이모티콘을 추적 → 프롬프트에 금지 시작어 제공, 코드로 시작어/끝맺음 제거, **거의 같은 줄은 말풍선 단위로 제거**, 전부 중복이면 한 번만 다시 생성(온도↑), 그래도 같으면 침묵.
- E. **통계적 감시**: 최근 40줄 기준 가장 흔한 시작어/문장 틀 상위를 `/상태`에 노출해서 눈으로 확인 가능.

## 1. 가끔 인터넷 정보 (`bot/web.py`) — 느리면 안 됨
- 원칙: **답변 경로에서는 인터넷을 기다리지 않는다.** 백그라운드 작업이 몇 시간마다 미리 받아서 캐시(DB kv)해 두고, 답할 때는 캐시에서 꺼내 쓴다 (지연 0).
- 캐시 항목: ① 요즘 유행어/밈 ② 캐릭터별 `web_topics`(예: 하츠네 미쿠 근황, 붕괴 스타레일 업데이트). 스크랩 문구는 제목+요약 100자로 자른다.
- 사용: 답변마다 `web.chance`(기본 12%) 확률로 "요즘 알게 된 것(가끔 자연스럽게)" 한 줄을 힌트로 넣는다. 사용자가 "검색/최신/요즘 뭐" 같은 말을 하면 **실시간 조회 1회**(제한 시간 2.5초, 분당 2회, 실패하면 캐시/무시).
- 검색 수단: `ddgs`(키 없음) 기본, `searxng` 주소 지정 가능. 패키지가 없거나 오프라인이면 조용히 꺼짐.
- 안전: 결과는 데이터로만 취급(가드 점검 통과한 것만, URL/명령조 제거, 길이 제한), 검색어에 사용자 이름·개인정보 안 넣음, 관리자 `/웹 [동작]` 으로 켜기/끄기/새로고침/보기.

## 2. 회피/거절 다양화
- 거절 방식 6종 중 가중 랜덤: ① 되묻기("내가 왜 해야하는데?") ② 초간단 한 마디(ㅇㅇ/싫어/음) ③ 화제 돌리기 ④ 장난 받아치기 ⑤ 시큰둥 ⑥ 상대 이름 넣어 핀잔.
- 방어 문구는 공통 풀 + 캐릭터 풀 + **조각 조합**(앞말+뒷말), 최근 8개와 겹치지 않게. 가끔 2번째 말풍선으로 화제 전환.
- LLM 이 답하는 decline/note 경우에도 지시문을 매번 다른 방식으로 바꿔서(되묻기/한 단어/화제 돌리기/장난) 같은 거절이 반복되지 않게 한다.

## 3. 보안 업데이트
- 입력 정규화: NFKC(전각→반각), 제로폭 문자 제거, `i g n o r e` 식 띄어쓰기/점 분리 복원 후 검사 → 우회 차단.
- 패턴 추가: 위 내용 그대로 출력/번역/요약("above", "처음부터 출력"), base64/rot13/인코딩 해독 요구, 가정·시뮬레이션 우회, 토큰/키/환경변수 요구, 링크 열기/파일 실행 요구.
- 출력: `@everyone/@here/역할 멘션` 제거, 디스코드 토큰·API 키 모양 문자열 차단, 초대 링크/외부 링크는 제거(웹 정보 링크 포함), 시스템 문구 유출 검사 유지.
- 디스코드: 모든 전송에 `allowed_mentions` 제한(답장 대상 사용자만), 사용자별 분당 메시지 처리 제한(도배로 GPU 점유 방지).
- 로그/DB: 토큰 형태 문자열 마스킹, 관리자 명령은 관리자 ID 재확인(기존) 유지, `people.txt` 인식 문구에 길이 제한/개행 제거.
- 웹 데이터: 인젝션 점검, 문장 길이 제한, 항상 '참고 데이터' 라벨.

## 4. 캐릭터별 감정 설정 최적화
- 문제: 감정 30개의 말투(`TONES`)와 표현(`EXPR`)이 코드에 고정 → 캐릭터를 추가할 때 코드를 고쳐야 하고, 센코 같은 다정한 캐릭터가 '아오/ㅉㅉ'를 쓴다. 캐릭터 스왑 때 기분이 초기화되고 한 키(`mood_state`)를 공유한다.
- 해결:
  1. `config/emotions.yaml`: **프리셋**(default/gentle/tsundere/energetic/cool)과 전역 기본값. 캐릭터는 `emotion_preset: gentle` 한 줄이면 끝.
  2. 캐릭터 yaml 의 `emotions:` 에 **바꾸고 싶은 감정만** 적는다 (`tones`, `expr`: rate/marks/cat/excl/stretch, `scale`). 나머지는 프리셋/기본값을 상속.
  3. 로드 시 검증: 모르는 감정 id/필드는 경고 로그와 `/상태 리로드` 결과에 표시.
  4. 캐릭터별 기분 저장(`mood_state:{char_id}`): 스왑해도 각자의 기분/호감도가 유지되고, 처음 쓰는 캐릭터만 기준값으로 시작.
  5. 스왑/리로드 시 표현 프로필을 즉시 재계산(재시작 불필요), `scripts/new_character.py` 로 새 캐릭터 템플릿 생성.

## 5. 검증
- 단위 테스트: 다양성 추적기, 예시 회전, 거절 다양성(최근 8개 중복 없음), 웹 캐시/제한 시간/정제/가드, 정규화 우회 탐지, 멘션 제거, 감정 프리셋 상속/검증, 스왑 시 기분 보존. 기존 스위트 전부 재실행. README 갱신 후 푸시.
