# 케이·아리스 대화 개선 기획서

## 로그에서 확인한 문제

- 케이는 해요체로 설정돼 있지만 반말을 예외로 허용하는 성격·감정 지시가 반복된다. `/기분`의 `반말` 태그는 모델 입력과 별개로 계산돼 설정과 다른 격식을 표시한다.
- 예시의 더듬음과 말줄임표를 모델이 따라 하고, 출력 단계에서도 머뭇거림과 감정 기호를 덧붙인다. 그 결과 `제 제가...`나 `...`처럼 내용이 비는 응답이 나온다.
- 케이의 아리스 편애가 확률형 키워드 훅과 배경 설명에 흩어져 있다. 아리스가 직전 화자여도 발화에 자기 이름이 없으면 훅이 빠진다. 아리스 쪽에는 케이에 대한 별도 관계가 없다.
- 캐릭터 대화 지시는 직전 상대의 말을 이어받도록 하지만 지정 주제와 과거 사건을 자주 섞으면 확인되지 않은 밤샘이나 패치 경험을 만들어낼 수 있다.

## 패치 설계

1. 케이의 기본 격식을 해요체로 통일한다. 츤데레는 짧은 핀잔, 구체적인 배려, 들켰을 때의 민망함으로 표현한다. 한 답에 이 세 요소를 모두 강제하지 않는다. 아리스를 챙길 때는 특히 부드럽게 말하되 케이의 건조함은 남긴다.
2. 두 캐릭터 카드와 예시를 압축한다. 이름을 물으면 평가를 바로 말하고, 개발 이야기는 버그나 조작감처럼 주어진 사실에 근거해 한 가지 의견을 낸다. 케이의 자동 더듬음과 감정 장식을 줄이고 기존 교정기가 해요체를 판별할 수 있도록 표현을 통일한다.
3. 케이의 조건부 컨셉 가중치를 0.60에서 0.85로 올린다. 훅은 생활 습관, 칭찬, 실제 게임 피드백처럼 구체적인 입력에만 반응시켜 대화마다 같은 소재를 반복하지 않도록 한다.
4. 케이와 아리스의 관계를 양쪽 카드에 고정하고, 직접 대화할 때는 캐릭터 ID로 관계 지시를 추가한다. 서로 전폭적으로 신뢰하고, 개발 의견이 다르면 문제와 해결책을 짚는다. 다른 유저의 호감도와 저장값은 그대로 사용한다.
5. 자동 받아치기와 수동 캐릭터 대화의 공통 지시를 짧게 정리한다. 직전 말을 바탕으로 새 의견이나 제안을 하나만 보태고, 함께한 경험을 지어내지 않도록 한다.

## 검증 기준

- YAML 검사와 전체 테스트를 통과한다. 케이 카드와 예시 분량을 수정 전후로 비교한다.
- 아리스가 자기 이름을 쓰지 않아도 케이에게 관계 지시가 전달되고 반대 방향도 동일하게 확인한다. 일반 유저와 다른 캐릭터에는 해당 지시가 붙지 않아야 한다.
- 케이에게 아리스 말투를 물으면 첫 답부터 짧은 평가가 나오고, 게임 개발 대화에서는 케이와 아리스가 서로 지지하면서 구체적인 의견을 낸다. 실제 문장 품질은 운영 모델에서 일반 대화와 수동 캐릭터 대화를 각각 실행해 확인한다.
