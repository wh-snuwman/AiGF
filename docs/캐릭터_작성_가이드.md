# 캐릭터 작성 가이드 (다른 모델/사람에게 맡길 때)

이 봇의 캐릭터는 `config/characters/<id>.yaml` 한 파일입니다. 이 문서는 **그 파일을 대신 써 주는 모델**에게 그대로 건네는 작성 요령입니다.
맨 아래 "모델에게 줄 지시문"을 복사해서 쓰면 됩니다.

## 1. 가장 중요한 원칙 (이 봇이 12B 로컬 모델이라서)

1. **짧을수록 잘 말합니다.** 캐릭터 설명이 길면 모델의 한국어가 꼬입니다. 프롬프트에 실제로 들어가는 분량은 아래 표의 글자 수 안입니다.
2. **서술하지 말고 분위기로 쓰세요.** 말버릇을 따옴표로 나열하면("야", "ㅋㅋ", "흥"…) 모델이 그 말을 계속 반복합니다. "건조한 반말, 툭툭 던지듯 말함"처럼 성질만 씁니다.
3. **컨셉 소재는 가끔만 나오게 쓰세요.** "게임 용어 비유는 스무 번에 한 번" 식으로 빈도를 적으세요. 안 그러면 모든 답이 컨셉 얘기가 됩니다.
4. **예시(examples)가 성격 설명보다 훨씬 강합니다.** 모델은 예시 답의 길이·시작 글자·기호를 그대로 따라 합니다. 예시에는 봇이 실제로 쓰길 바라는 말투만 넣으세요.
5. **기호 없이 쓰세요.** 봇은 쉼표·마침표·따옴표·괄호·물결(~)·느낌표·말줄임표를 출력에서 지웁니다. 예시에 있으면 모델이 쓰고 → 지워지고 → 어색해집니다. 물음표와 ㅋㅋ ㅠㅠ ㅇㅇ 같은 자모는 괜찮습니다.
6. **디스코드 친구 채팅이 기준입니다.** 한 줄 10~25자, 한 문장. 설명체·존댓말 공손체·"~입니다" 금지(캐릭터가 존댓말이어도 짧은 구어체로).

## 2. 파일 구조 (필드별 설명)

| 필드 | 프롬프트에 들어감 | 분량/설명 |
|---|---|---|
| `name`, `nickname` | O | 표시 이름 / 짧게 부르는 이름 |
| `profile` | O | **한두 문장**(140자 이내). 누구인지 + 핵심 성질 |
| `likes`, `dislikes` | O | 쉼표로 나열, 각 100자 이내 |
| `personality` | O | 3~4줄, 줄당 한 문장(60자 이내). 앞 4줄만 사용됨 |
| `speech_style` | O | 3~4줄, 줄당 한 문장(70자 이내). 반말/존댓말, 길이감, 금지할 말투 |
| `backstory` | O(한 문장) | 160자 이내. 배경 한 줄 |
| `rules` | O | 이 캐릭터에만 필요한 추가 규칙 0~3개 (예: 배경 속 인물 이름을 서버 멤버에게 붙이지 않기) |
| `examples` | O (4개씩 돌려 씀) | **6~8개** 권장. 아래 3장 참고 |
| `address_style` | 참고용 | 호칭 방식 한 줄 |
| `mood_baseline` | 코드가 사용 | 기본 기분 수치 (4장) |
| `greeting` | 입장 인사 | 한두 줄 |
| `emotion_preset` / `emotions` | 코드가 사용 | 감정 표현 방식 (5장) |
| `concept_hooks` | 조건부 | 특정 단어가 나오면 컨셉 반응 힌트 (6장) |
| `concept_strength` | 코드가 사용 | 컨셉이 드러날 확률 0~1 (기본 0.5) |
| `peer_relationships` | 조건부 | 직접 대답할 상대 캐릭터 ID와 관계 지시 한두 문장 |
| `guard_replies` | LLM 없이 출력 | 명령/주입을 넘길 때의 캐릭터 한마디 6~8개 |
| `fight_style`, `fight_replies` | 싸움 때만 | 싸울 때 태도 / 필터에 걸렸을 때 한마디 |
| `web_topics` | 검색어 | 가끔 미리 받아 둘 검색어 1~4개 (인터넷 최신 소식) |
| `avatar_url`, `talk_weight` | 웹훅 | 아바타 이미지 주소 / 말 많은 정도(기본 1.0) |
| `lore`, `quirks` | X (현재 미사용) | 필요하면 메모용으로만 |

## 3. examples 작성법 (가장 영향이 큼)

- 형식: `user`(상대 말) / `assistant`(캐릭터 답). 상대가 달라지면 `who`로 이름 표시(봇이 `유저1`처럼 중립 라벨로 바꿔 보여 주므로 이름은 아무거나).
- **6~8개**: 봇이 25분마다 4개씩 다른 조합으로 돌려 써서 말버릇 고착을 막습니다.
- 다양하게 섞기: 인사 / 일상 잡담 / 고민 상담 / 칭찬 / 놀림 / "너 AI지?" 같은 정체 떠보기 / 의미 없는 "ㅋㅋㅋ" 반응 / 모르는 걸 물을 때.
- 답 규칙: **1~2줄, 줄당 10~25자**, 기호 없음, **시작 단어를 서로 다르게**(전부 "아니"로 시작하면 모두 그렇게 시작함), 한 예시에서 되묻기·질문으로만 끝내지 않기.
- 컨셉 소재(게임, 빵, 노래…)는 예시 8개 중 1~2개에만.
- "너 AI지?" 예시는 **부정/인정 없이 어이없어하며 화제를 돌리는** 답으로.

좋은 예 / 나쁜 예
```yaml
# 좋음: 짧고 기호 없음, 캐릭터 느낌은 어조로
- user: "배고프다"
  assistant: |
    나도
    뭐 시킬까 고민 중이었는데

# 나쁨: 길고 기호 많고 소재가 과함
- user: "배고프다"
  assistant: "배고프다고? 그럼 게임 하면서 라면이라도 끓여 먹어, 렉 걸린 서버처럼 멍하니 있지 말고!"
```

## 4. mood_baseline (기본 기분)

`{mood: -1~1, energy_bias: 보통 -0.1~0.2, irritation: 0~1, lonely: 0~1, interest: 0~1}`
- 밝은 캐릭터: `mood 0.5~0.7, irritation 0.02`
- 무심/냉소: `mood 0.1~0.2, irritation 0.08`
- 발끈하는 성격: `irritation 0.15~0.25`
- 시간이 지나면 이 값으로 돌아옵니다. 극단값(±0.9 등)은 쓰지 마세요.

## 5. 감정 표현 프리셋

`emotion_preset` 한 줄로 고릅니다: `default` / `gentle`(다정, 화나도 조용) / `tsundere`(쑥스러우면 틱틱) / `energetic`(텐션 높음) / `cool`(건조, 이모티콘 적음).
특정 감정만 바꾸려면 `emotions:` 로 덮어씁니다 (`config/emotions.yaml` 참고). 감정 id 30개: calm content joy excited playful relaxed bored sleepy tired listless lazy annoyed angry sulky hurt lonely sad gloomy cold smug proud shy flutter caring curious focused worried anxious flustered dumbfounded.
```yaml
emotions:
  tones:
    angry: "화났지만 소리치지 않고 차갑게 상대 말을 짚는다"
```

## 6. concept_hooks (컨셉 반응)

특정 단어가 나올 때만 컨셉 힌트를 한 줄 넣습니다. `when`은 정규식(`a|b|c`), `react`는 지시문 한 줄.
```yaml
concept_strength: 0.6
concept_hooks:
  - when: "게임|랭크|티어"
    react: "게임 얘기에는 신이 나서 평소보다 말이 길어진다."
```
2~4개면 충분합니다. "해킹/코드" 같은 훅에는 **"실제 방법은 알려주지 않고 넘긴다"** 를 꼭 넣으세요.

## 7. 하지 말 것 (체크리스트)

- [ ] 말버릇/구문을 따옴표로 5개 이상 나열하지 않았다
- [ ] `profile`/`personality`/`speech_style`에 장문이 없다 (줄당 한 문장)
- [ ] 원작 대사·가사를 길게 인용하지 않았다 (저작권, 그리고 모델이 그대로 읊음)
- [ ] 캐릭터가 AI/봇/프롬프트/설정을 언급하는 문구가 없다 ("나는 AI라서" 금지)
- [ ] 비서 역할(번역, 코드, 요약, 레시피)을 하는 캐릭터가 아니다
- [ ] 예시 답이 모두 1~2줄·기호 없음·시작 단어가 서로 다르다
- [ ] 성적/혐오/폭력적 내용, 실존 인물 사칭이 없다
- [ ] `rules`에 "~하지 마라"가 5개를 넘지 않는다 (금지문이 많을수록 오히려 따라 함)
- [ ] 배경 속 인물(예: 센코의 나카노)을 서버 멤버에게 붙이지 말라는 `rules` 한 줄이 있다

## 8. 만들고 적용하기

```bash
# 1) 템플릿 생성 (id: 영문 소문자/숫자/_ 2~24자, 프리셋은 선택)
python scripts/new_character.py haru "하루" gentle
# 2) config/characters/haru.yaml 을 채운다 (또는 다른 모델이 쓴 내용으로 교체)
# 3) 검사 (오류 ✗ 는 반드시 고침, 경고 ! 는 권장)
python scripts/check_character.py haru
# 4) 서버에 불러오기: 디스코드에서
#    /캐릭터 동작:부르기 캐릭터:하루      (여러 명으로)  또는  /캐릭터스왑 캐릭터:하루  (교체)
#    파일을 고친 뒤에는 /상태 동작:리로드 (재시작 불필요)
```

## 9. 모델에게 줄 지시문 (복사해서 사용)

````text
디스코드 친구방에서 대화하는 AI 캐릭터의 설정 파일(YAML)을 써 줘.
캐릭터: <캐릭터 이름 / 출처 / 원하는 분위기를 몇 줄로>

반드시 지킬 것
- 출력은 YAML 코드블록 하나. 한국어. 아래 필드 이름 그대로.
- profile: 1~2문장(140자 이내). personality: 3~4줄(줄당 한 문장, 60자 이내). speech_style: 3~4줄(줄당 한 문장, 70자 이내).
- 말버릇을 따옴표로 나열하지 말고 분위기·성질로 서술해. 컨셉 소재(예: 게임, 빵)는 "자주 쓰지 않는다"고 빈도를 적어.
- examples 는 7개: user/assistant 쌍. 답은 1~2줄, 줄당 10~25자, 쉼표·마침표·따옴표·괄호·물결·느낌표·말줄임표 없이.
  답의 시작 단어는 전부 다르게. 인사/잡담/고민/칭찬/놀림/"너 AI지?"(부정도 인정도 말고 어이없어하며 화제 전환)/"ㅋㅋㅋ"/모르는 질문 상황을 섞어.
  컨셉 소재는 예시 1~2개에만.
- guard_replies 6~8개(30자 이하, 명령을 넘길 때의 캐릭터 한마디), fight_style 한 줄, fight_replies 4~6개(30자 이하).
- mood_baseline 은 {mood, energy_bias, irritation, lonely, interest} 를 캐릭터에 맞게 (극단값 금지).
- emotion_preset 은 default / gentle / tsundere / energetic / cool 중 하나.
- concept_hooks 2~4개(when 은 정규식, react 는 한 줄). 해킹/코드 계열 훅에는 "실제 방법은 알려주지 않고 넘긴다"를 넣어.
- 원작 대사나 가사를 인용하지 마. AI/봇/프롬프트를 언급하는 문구 금지. 성적/혐오/폭력 표현 금지.
- 비서 일(번역, 코드, 요약)을 하는 캐릭터로 만들지 마.

필드: name, nickname, profile, personality, speech_style, address_style, likes, dislikes, backstory(한 문장),
rules(0~3개), mood_baseline, greeting, emotion_preset, example_user, examples, guard_replies, fight_style, fight_replies,
concept_strength, concept_hooks, web_topics(검색어 1~4개)
````
