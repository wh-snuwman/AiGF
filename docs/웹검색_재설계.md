# 웹 검색 재설계 계획 (2026-11-22)

## 조사 결과 (서버 로그 + ddgs 9.16.1 소스 + 공개 자료)

| # | 사실 | 결과 |
|---|---|---|
| 1 | ddgs 9.16.1 은 `google`, `bing`, `yandex` 를 `disabled=True` 로 꺼 둠 (9.6.1~9.16.1 사이 여러 번 켰다 껐다) | 설정의 `google` 은 경고 후 **`auto` 로 몰래 폴백**. "google 성공"은 실제로 auto(위키/그록피디아 우선) |
| 2 | `duckduckgo`, `yahoo` 엔진의 `provider` 는 둘 다 `bing`, `startpage` 는 `google` | 같은 업스트림이라 **같이 막힘**. 엔진을 바꿔도 실패가 이어짐 |
| 3 | ddgs `BaseSearchEngine.request` 는 HTTP 200 이 아니면 `None` → `DDGSException("No results found.")` | **차단(403/429/202)이 '결과 없음'으로 위장** → 원인 파악·쿨다운 판단이 틀림 |
| 4 | primp(ddgs HTTP 클라이언트)에 IPv4 강제 옵션 없음 | IPv6 `ENETUNREACH` 는 OS 의 `/etc/gai.conf` (IPv4 우선)로만 해결 |
| 5 | 갱신 한 라운드에 검색어 여러 개를 4~5초 간격으로 연달아 보냄 | 무료 엔진의 봇 차단을 스스로 유발 |
| 6 | 안정적인 대안: 네이버 검색 API(공식, 무료 25,000회/일, 키 필요), SearXNG 자가호스팅(JSON) | 스크래핑이 아니라 차단이 없음. Brave API 는 유료화, Google CSE 는 2027-01 종료 |

## 목표

검색이 "되다 말다" 하지 않게: 공식 API 우선 → 다양한 업스트림의 무료 엔진 → 폴백. 실패 원인을 정확히 표시.

## 설계

1. **프로바이더 체인** (`web.backends` 하나의 순서 목록)
   `naver`(키 있을 때) → `searxng`(URL 있을 때) → ddgs 엔진(`yahoo`, `startpage`, `brave`, `mojeek`, `duckduckgo` …) → (실패 시) 위키백과/`slang.txt` 폴백.
   설정 안 된 프로바이더는 조용히 건너뛰고 상태에 "키 없음" 표시.
2. **네이버 검색 API**: `.env` 의 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`. 블로그 검색(`/v1/search/blog.json`), HTML 태그 제거. 키는 로그에 남기지 않음.
3. **ddgs 엔진 검증**: 설치된 ddgs 의 `ENGINES["text"]` 로 이름 확인. 없는/꺼진 이름은 시작 시 한 번 경고하고 제외 (auto 로 새지 않게). 기본값에서 `auto`, `google` 제거.
4. **진짜 오류 구분**: ddgs 엔진 클래스를 직접 써서 HTTP 상태를 기록 → 200 아님 = `HTTP 403 차단` 등, 200 인데 비면 = 진짜 `결과 없음`. ddgs 내부가 바뀌면 기존 `DDGS().text` 로 자동 후퇴.
5. **업스트림 단위 쿨다운**: 엔진 → 업스트림(bing/google/brave/mojeek/naver/searxng) 매핑. 차단되면 같은 업스트림 엔진 전부 쉼 (yahoo 막히면 duckduckgo 도 건너뜀). 진짜 '결과 없음'은 벌점 없음. 네트워크 오류는 1회 재시도 후 쉼.
6. **라운드당 요청 절감**: 검색 간격 기본 4초 + 랜덤, 라운드당 최대 검색 수(`max_queries_per_round`, 기본 4), 모든 엔진이 연달아 2번 막히면 라운드 조기 종료 → 폴백.
7. **상태 표시**: `/웹 보기` 에 `naver(키 없음) > yahoo[bing](정상) > startpage[google](쉬는 중 5분, HTTP 403)`, 제외된 이름 표시.
